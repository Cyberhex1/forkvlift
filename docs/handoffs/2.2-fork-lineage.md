# [2.2] "Continue this" (fork to your GitHub) + project comments: Opus

## "Continue this": `POST /api/projects/:slug/fork`

- **No write tokens:** ForkLift never asks for or stores a write-scoped GitHub token. The fork happens on GitHub.
  - **Before the fork exists:** the call returns **409** with `details.forkUrl` (`https://github.com/<owner>/<repo>/fork`). The UI opens that page, then the user presses Continue again.
  - **Once `<viewer>/<repo>` exists as a fork of the original:** it creates a **private draft project** for the fork (WIP stage, original's category and stack, lineage in `forks`), adds an **Idea card** in the first Studio column (WIP limits don't block it), and notifies the original author ("ada forked bo-tool").
- **Pressing it again** returns the same card.
- **Refused:**
  - unlicensed projects (403; the UI offers "Request to build on this")
  - your own project (400)
  - a same-named repo that isn't a fork (409)
- **Response:** `{ forkRepoUrl, studioCardId }`. The forker publishes from Studio whenever they're ready.

## Comments: `POST /api/projects/:slug/comments` (left over from 1.9)

- **Rules:** Turnstile; replies must point at a comment on the same project; the comment count is recounted after each post.
- **Notifications:**
  - the project author ("commented on")
  - the parent commenter ("replied to your comment")
  - `@mentions` (up to 10)

  Blocked and muted users never notify you.

## For Sol

- **Continue this (panel):** on 409, open `error.details.forkUrl` in a new tab and show "Fork it on GitHub, then press Continue again". On 200, link to `/studio`.
- **Comments:** post from the panel, using the Turnstile widget as in 1.11.
