# 1.12 Admin review queue

## Changes
- API-authorized review queue with URL-backed status/sort, paginated loading, editable proposed card previews, check chips and source credit links.
- Individual approve/publish, approve/draft, reject/reason and snooze/N-days decisions. Licensed approval requires a category and no existing imported project. The latest owner decision is enforced: unlicensed candidates remain reviewable, with the exact shared disclaimer, but individual and bulk approval are disabled.
- Bulk selection (max 100) and actions report the returned updated count and skipped count without implying every item succeeded. Importer stores optional credit links and only invokes the GitHub import API.
- Loading, empty, failure/retry, missing images/categories, pending actions and access-denied states. An authorization failure hides previously cached private candidates. Account theme/motion settings use the shared token selectors; admin title/navigation use SITE_NAME.
- Playwright starts the admin dev server automatically on the web port + 3, including in CI. Queue code is loaded through the existing admin route; no shared API/token/component/dependency changes.

## Test
Run `pnpm dev` and `pnpm dev:admin`. Visit `http://127.0.0.1:8791/api/dev/login?as=fx-admin`, then `/`. Review the fixture, edit its card, reject/snooze, select bulk candidates, change status/sort and import a repository. API fixtures are stateless; Refresh restores the original queue. The supplied candidate has no license, so approval correctly stays disabled. Tests derive a licensed candidate from API responses to exercise approvals without editing shared fixtures.

`pnpm check` passes (175 unit/integration tests, typecheck, lint, builds, fixture isolation). The full browser suite passed 25 tests with one intentional desktop touch-only skip. The final 10 admin executions include authorization loss with cached data, account reduced motion, previews, approval/draft/reject/snooze, bulk skipped counts, importer, pagination, no-license restrictions and loading/empty/error at both viewport widths. Computer use exercised mobile review/snooze and desktop approval, draft, bulk rejection and import using the local test-only QA proxy, plus its loading/empty/error states.

`node e2e/review-state-proxy.mjs` serves local browser QA at `http://127.0.0.1:8797/__qa?mode=licensed` (or fixture, loading, empty, error). This test helper proxies the fixture APIs and never ships. No production candidate was published or modified during validation.

## Boundaries
No unfinished work in this task. Candidate contracts have no project-stage field: review status is shown, and approved curated imports currently start as finished per the backend. WIP belongs to project submissions/detail, not an invented candidate field. Bulk snooze uses the API's default seven days; individual snooze accepts 1–365 days. Moderation/categories/staff-pick/stats/audit pages remain their separate assigned tasks. Production permission checks and fresh repository/license re-ingestion remain authoritative on the Worker.
