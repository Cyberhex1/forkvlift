# 2.5 Follows, bookmarks and collections API

## Changes
All ten social routes now use D1. Follows validate live user/category/listed-project targets, reject self-follows, are idempotent, and use stable pagination. The private built-in Saved collection is created atomically on first owner access or collection creation, cannot be renamed/deleted, and remains isDefault. Public/private collection authorization applies to reads and every item/edit/delete route. Public non-owner writes return 403; private non-owner requests return 404.

Collection cards use rowsToCards, including tags, WIP state, authors and viewer saved/upvote flags. Other viewers see only listed, licensed cards; owners can see unlicensed cards and their own private repository projects. Hidden/deleted projects remain excluded. Counts reflect the viewer-visible contents. Adds/removes are idempotent, maintain ordering, update collection timestamps and respect project visibility.

The two contract requests in this PR ask Opus for the task 2.6 drag dependencies and the 2.9 header notification slot. No shared contracts, migrations, dependencies or shell files were edited.

## Validation and how to test
- `pnpm --filter @forkvlift/worker test`: 118 unit tests and 64 integration tests passed, including 12 new social tests using real migrated D1 and resetDb/seedUser/seedProject.
- `pnpm check`: passed (typecheck, lint, tests, builds, fixture exclusion).
- `pnpm test:e2e social-api --workers=2`: 6 passed across 375 and 1440 px. Browser tests validate authenticated route plumbing and the existing focus-panel Saved flow for licensed/WIP/unlicensed projects, plus loading/error/retry/empty states.
- Computer use: clicked through collection loading, error, empty, and successful Saved actions at both widths with the real dev app and the test-only state proxy.

Run `pnpm dev`, sign in at `/api/dev/login?as=fx-ada`, open a project panel, and choose Save to collection → Saved. Browser dev routes intentionally use stateless fixtures. Real persistence, privacy, default-collection protection, concurrency, pagination and saved flags are verified by D1 integration tests. To manually click failure/empty/loading states run `node e2e/browser-state-proxy.mjs` and use `http://127.0.0.1:8798/__qa?area=collections&mode=error` (or empty/loading/fixture). This helper stays under e2e and does not ship.
