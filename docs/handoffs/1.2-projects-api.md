# [1.2] Projects API: Opus

## What changed

- **`GET /api/projects`** (`core/projects/list.ts`):
  - **Search:** D1 FTS5 over name, tagline, description, tags, "replaces" and README text. Results rank by relevance when there's a query and no sort.
  - **Filters:** category (a parent includes its sub-categories), license, stage, stack, platform, AI tool, difficulty, has demo, has release, maintained (a commit in the last 90 days), replaces a paid product or a named product, source, and template.
  - **Sorts:** trending (votes weighted by recency), newest, most forked, most starred, recently updated, most discussed, staff picks, and random. Random keeps the same order while you page through it.
  - **Pagination:** offset cursors, capped at 10k.
  - **Unlicensed projects** are excluded unless `showUnlicensed=true`. `hiddenUnlicensedCount` says how many were hidden.
  - **Listed** means: public, published, has a repo, and not hidden or deleted.
- **`GET /api/projects/:slug`:** full panel data, including media, the project it was forked from, notable forks, the WIP box, and the verified-author flag (the GitHub owner of the repo is the person who listed it). Unlicensed projects open by direct link. Private and unpublished projects are visible only to their owner and admins.
- **`POST /api/projects/:slug/vote`:** idempotent. The vote count is recounted from the votes table.
- **`GET /api/projects/:slug/comments`:** real comments, paginated.
- **`GET /api/users/:username/projects`:** "projects" and "forks" tabs. Owners always see their own unlicensed projects.
- **`GET /api/categories`:** the counts are real now.
- **`similarProjects`:** keyword-based for now; semantic search arrives in 4.1.
- **Contract:** `listUserProjects` gained `showUnlicensed`.
- **Migration `0001_projects_fts`:** adds the FTS table. `syncProjectSearch()` must run after every project write (1.4 and 1.7 call it).
- **Tests:** new D1 integration test suite using `@cloudflare/vitest-plugin` (it runs in workerd with real migrations): `test/integration/`. `pnpm test` runs the unit tests and the integration tests.

## How to test

`pnpm --filter @forkvlift/worker test`. That's 16 integration tests covering hiding, search, filters, sorts, pagination, detail visibility, votes, and profiles.
