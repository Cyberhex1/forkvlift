# [1.1] GitHub ingestion: Opus

## What changed

- `apps/worker/src/core/github/`
  - `repo-url.ts`: parses anything pasted (full URL, `.git`, `/tree/...`, SSH, `owner/repo`) into `owner/repo`. Non-GitHub hosts and invalid names are rejected.
  - `client.ts`: GitHub REST client. Responses are cached in KV with ETags, so repeat fetches come back as 304s and cost no rate limit. If GitHub's rate limit is hit, it serves the cached copy. An optional `GITHUB_TOKEN` secret raises the limit from 60 to 5,000 requests/hour.
  - `sanitize.ts`: allowlist sanitizer for GitHub-rendered README HTML (uses the `xss` package). It strips scripts, styles, iframes, SVGs, event handlers and `javascript:`/`data:` URLs. Only GitHub's own highlight CSS classes survive, so READMEs can't borrow our utility classes. Relative links and images are resolved against the repo. External links get `rel="nofollow noopener noreferrer ugc" target="_blank"`. Output is capped at 200 KB.
  - `ingest.ts`: `ingestRepo(env, urlOrRef)` returns a `RepoSnapshot` with the canonical name, stats, contributors count, archived/fork/parent, dates, license (null means no license), sanitized README, a "has screenshots" hint and the GitHub OG image as a thumbnail fallback.
- Licenses: GitHub's `NOASSERTION` (a license file GitHub can't identify) is now a "Custom license" instead of "no license", so those projects aren't wrongly hidden.
- Jobs: `repo.ingest` refreshes a listed project's GitHub data (and its candidate snapshot). `stats.refresh` (daily cron) queues a refresh for every listed repo. Failures retry with backoff; missing or private repos are dropped.

## How to test

`pnpm --filter @forkvlift/worker test` (tests for URL parsing, the sanitizer, ETag caching, and not-found handling). I also ran it once live against `cloudflare/vibesdk`: MIT, 5.4k stars, 18 contributors, README sanitized (15.8 KB).
