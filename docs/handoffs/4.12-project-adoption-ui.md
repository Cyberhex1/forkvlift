# 4.12 Up for adoption UI

Project focus panels show adoption state, note, original attribution and listed maintainer. Signed-in applicants can send a private application and withdraw a pending one. Controls retain application text on errors. Current maintainers (server `canManage`) can open/close adoption, edit the note, page private requests, decline, or review and confirm an approval. Conflict errors offer a status refresh. Every mutation refreshes the project/catalog data from the server rather than inventing new ownership locally.

The approval dialog explicitly describes transfer of the ForkLift listing and closing competing applications. GitHub permissions and licensing do not change. Admins do not receive maintainer controls just for being admins.
