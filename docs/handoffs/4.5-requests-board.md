# 4.5 Requests board and text bounties

Implemented the four existing request routes in growth.ts. Creation requires a signed-in user and verified Turnstile token. Titles are trimmed and validated. Public reads omit deleted authors and inaccessible completed project links. Claiming uses an atomic compare-and-set, rejects self/blocked/built claims, returns conflict to losing claimants and supports idempotent replay by the winner. Bounties remain text in bodyMd; the site processes no payments and offers no paid placement.

The UI adds /requests/:id, status filters, pagination with retry retaining current results, safe Markdown details, sign-in gates, claim progress/errors and request creation. Optional bounty text is appended as a Markdown section. Verification setup loading/failure/retry, token expiry/reset and retained input after server errors are covered. The existing contract can create and claim requests; no completion route was added. Built project links are displayed when returned by the contract.
