# 5.2 Showcase search (Opus)

Showcases are now found by meaning, not just by keyword, and the "Has this been built?" check returns them next to catalog projects.

## What changed

- **Embeddings:** published showcases are embedded with the same model as projects (4.1) and stored in the same Vectorize index under the `showcases` namespace, so project and showcase vectors never mix. The 15-minute `vectors.sync` job keeps them current: it re-embeds only when the text changes and drops vectors for showcases that are hidden, unpublished, deleted, or whose maker is banned. Migration `0014` adds `embedded_at` and `embedding_hash` to `showcases`.
- **Feed search (`listShowcases` with `q`):** when the sort is relevance (no `sort`, or `trending`), meaning matches come first, then keyword matches. The cursor carries the meaning matches, so paging never repeats a showcase. `sort=new` or `sort=top` stays a plain keyword search. Filters (category, kind, tool, staff picks) apply to both.
- **"Has this been built?" (`similarProjects`):** the response gains `showcases: ShowcaseCard[]` (up to 6) alongside `items`. Existing callers keep working.
- **Fallback:** without Workers AI or Vectorize (local dev, tests), everything falls back to keyword search.
- **Ranking:** the trending, new and top sorts shipped in 5.1 are unchanged.

## For Sol (5.4, 5.6) and the "Has this been built?" box

- Show `similarProjects().showcases` under a "Showcases" heading in `AlreadyBuilt`, with the "Showcase" badge and "Closed source" when `hasPublicCode` is false. These are look-don't-take results, so give them no clone or fork actions.
- The showcase feed's search box can pass `q` with no `sort` to get relevance order.

## How to test

`pnpm --filter @forkvlift/worker test` runs `test/integration/showcase-search.test.ts` (namespacing, re-embedding, hiding, paging without repeats, filters, the keyword fallback).
