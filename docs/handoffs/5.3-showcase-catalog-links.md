# 5.3 Showcases and the catalog (Opus)

Showcases and catalog projects now link to each other in three ways.

## What changed

- **"Built with" credits:** `ShowcaseInput.builtWith` takes `{ projects: slug[], resources: slug[] }` (up to 10 each). If it's left out of an edit, the credits stay as they are; an empty list clears them. Unknown, private, hidden or deleted targets are refused with a 400. `ShowcaseDetail.builtWith` returns `{ projects: ProjectRef[], resources: { id, slug, title }[] }`, and a project or resource that is later removed drops out quietly. Table `showcase_credits` is created by migration `0015`.
- **"Used in these showcases":** `projectShowcases` (`GET /api/projects/:slug/showcases`) and `resourceShowcases` (`GET /api/resources/:slug/showcases`) list the published showcases that credit that project or resource, top-voted first.
- **List in the catalog:** `listShowcaseInCatalog` (`POST /api/showcases/:slug/catalog`, Turnstile) turns a published showcase into a catalog project. The repo is the showcase's own, or `repoUrl` from the request. It goes through the normal submission rules, so the maker must own the repo, the repo can't already be listed, and the daily limit applies. On top of that, the repo **must have an open-source license**, because the catalog is for reusable code. The new project copies the title, tagline, text, category, stage, tags, cover and images, the "live" and "download" links, and AI tools that match the catalog's list. The showcase then shows `hasPublicCode: true` and `catalogProject` ("See the code").
- **Open-source it later:** if the showcase had no repo before (it was closed source), its upvotes (not the maker's own) and live comments, replies included, are copied onto the new project. The response reports them in `carriedOver`. The showcase stays published and links to the code.

## For Sol (5.4, 5.5) and catalog pages

- Composer: a "Built with" picker (search the catalog and resources, then send slugs) and a "List the code in the catalog" button for the maker. Show it when the showcase is published and `catalogProject` is null. Ask for the repo URL when `repoUrl` is null, and explain that votes and comments carry over.
- Project focus panel and resource page: a "Used in these showcases" strip from the two new routes, shown only when there are any.
