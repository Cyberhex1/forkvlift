# 5.5 Showcase composer

Create at `/showcase/new`, manage drafts at `/showcase/mine`, edit at `/showcase/:slug/edit`. Studio cards link to creation with title, idea, stage and project credits prefilled. Covers, gallery files and YouTube/Vimeo embeds can be added and removed; descriptions are editable. Uploads reserve typed API slots then use the returned authenticated URL with XHR for byte progress. Upload failures retain previously attached files. Save/publish failures retain the form. The shared input schema checks every submission.

Built-with pickers search the catalog/resources, send slugs and cap each kind at 10. Lists hide unlicensed projects until opted in. Link checks validate HTTP(S) format; they do not claim reachability or safety. Preview renders the form's content with the same page components. Owners list a newly public licensed repo from the showcase page after its license and ownership checks. Server license/ownership checks remain authoritative.

## Review fixes (2026-10-13)

- Form submission creates new showcases as drafts and preserves the status of existing showcases; publishing requires the explicit Publish button. Each credit search handles Enter itself without submitting the composer. AI tools and Tags are controlled and update before blur, including across preview toggles.
- Removed the editor's ungated catalog card and its mutation; the showcase page remains the entry point and sends the saved repository URL after checking license and ownership.
- Comment deletion uses the mutation's comment id so only the affected Delete button spins; other Delete buttons are disabled until it settles.
- Preview classifies new uploads from their content type (including GIFs) and preserves the server's media kind for existing gallery items.

Regressions cover Enter in both credit searches (no showcase request), title/embed/AI tools/Tags (draft only, latest input retained), removed editor listing, extensionless media keys, and per-comment delete progress. The existing publish flow and showcase-page license/error gates also pass. `pnpm check` passes. Fixes originate on 5.5 and are merged forward through 5.6 → 4.12 → 4.6 → 4.14 without rebasing.
