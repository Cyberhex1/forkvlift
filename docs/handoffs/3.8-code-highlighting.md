# 3.8 follow-up: lazy, safe code highlighting

Markdown code fences now use Refractor 5.0.0 (Prism AST core) and lazy per-language grammars. JavaScript, TypeScript, JSX/TSX, JSON, Bash, Python, CSS, HTML/XML/SVG, SQL and PowerShell are supported with common aliases. Unknown/unlabelled blocks and blocks over 20,000 characters stay plain monospace. Plain code remains visible during loading and after download/tokenization failure. No theme CSS, raw user HTML or AST attributes are inserted: the renderer creates only React text and spans with allowlisted existing UI color classes.

The user explicitly authorized an ownership/dependency exception for markdown.tsx, its code-highlight.tsx helper, apps/web/package.json, pnpm-lock.yaml, and the narrow OWNERS.json update. Exact rules record that exception so Sol CI passes. No shared, UI token, Worker or Durable Object files changed.

## How to test

Visit `/forum/t/fx_thr_1` against fixtures and inspect its JavaScript fence. Use fenced js/ts/tsx/json/py/sh/html/css/sql/ps1 snippets in a post or resource. Unknown languages remain plain. Switch theme and confirm token colors follow the UI theme. All text, whitespace and code contents remain unchanged.

`markdown-highlighting.spec.ts` injects controlled code through the fixture thread response and verifies ten grammar/alias examples, literal HTML safety, token colors in light/dark/retro, phone overflow, unknown/unlabelled/large blocks without highlighter requests, delayed import fallback and failed download fallback. Focused suite: 8/8 passed at 375 px and 1440 px. Tests never import fixtures into client code.
