# 5.9 Showcase-only events (Opus)

Events like "Show-off Saturday" now run on the 4.6 events system, with showcases as entries instead of projects.

## What changed

- **New event kind `show_off`:** admins schedule it like any other event (`createGrowthEvent`). It has the same three windows (submissions, voting, ended) and no featured project.
- **Entries:**
  - `listShowcaseEventEntries` (`GET /api/events/:slug/showcase-entries`, `sort=rank` gives the leaderboard).
  - `submitShowcaseEntry` (`POST`, Turnstile, takes `showcaseId`).
  - `withdrawShowcaseEntry` (`DELETE …/:id`).
  - Makers can only enter their own published showcases, each once per event, and can withdraw only while submissions are open.
- **Voting:** uses the existing ballot route (`voteGrowthEntry`, `PUT /api/events/:slug/ballot`): one vote per person per event, no voting for your own entry. Banned or deleted voters stop counting, and hidden, unpublished or deleted showcases drop out of the list and the ranks. `getGrowthEvent` fills in `viewerCanSubmit`, `viewerBallot` and `entryCount` for showcase events too.
- **Guards:** project entries are refused on a showcase event, and showcase entries on a project event. Competitions (4.14) can't be attached to a showcase event.
- **Storage:** migration `0016` adds the `showcase_entries` and `showcase_ballots` tables.

## For Sol (4.6 UI) and Flash (5.8 copy)

- When `event.kind === "show_off"`, the events page should list `listShowcaseEventEntries` with showcase cards, and use a "Pick one of your showcases" picker (`myShowcases`, published only) instead of the project picker. Voting works the same as for project events.
- Flash: give "Show-off Saturday" a name and short rules in the 5.8 copy.
