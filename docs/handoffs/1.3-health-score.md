# [1.3] Health score: Opus

## What changed

- `core/projects/health.ts`: `computeHealth()` gives a 0–100 score with a visible breakdown:
  - **Stars:** up to 30 points, log scale; 5,000 stars earns full marks.
  - **Forks:** up to 20 points, log scale; 1,000 forks earns full marks.
  - **Contributors:** up to 15 points, log scale; 20 contributors earns full marks.
  - **Activity:** up to 25 points, based on days since the last commit (7, 30, 90, 180 and 365-day steps). Archived repos get 0 here.
  - **Age:** up to 10 points; older repos have shown they stick around.
- `repo.ingest` stores `health` and `health_score` and re-indexes search whenever a project's GitHub data refreshes. The daily `stats.refresh` cron keeps every project's score current.
- `ProjectDetail.health` already carries the breakdown. For each part, `value` is the raw number (stars, forks, contributors, days since the last commit, age in days; -1 means unknown) and `points` is what it earned.

## For Sol (1.9)

Show `health.score` along with the five parts. For example: "Activity 20/25 · last commit 12 days ago". The weights are in `HEALTH_WEIGHTS`. If you want them in the shared package, file a contract request.

## Tests

`test/health.test.ts`: a big active repo gets full marks, a brand-new project scores low but not zero, stale and archived repos lose activity points, every part stays within its weight, and missing dates are handled.
