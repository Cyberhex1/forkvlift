# [1.5] Uploads to R2: Opus

## What changed

- R2 is now bound in preview and production (the owner enabled R2 and created `forkvlift-media-preview` and `forkvlift-media-prod`).
- `core/uploads.ts`:
  - **`POST /api/uploads`:** reserves a key for 15 minutes. Allowed types and sizes:
    - Thumbnail: PNG, JPEG, WebP or GIF, up to 5 MB
    - Avatar: the same image types, up to 2 MB
    - Media: images plus MP4 and WebM, up to 25 MB
    - Resource: zip, Markdown or plain text, up to 10 MB
  - **`PUT /api/uploads/:key`:** only the user who reserved the key can upload. The Content-Type must match the reservation, the size can't exceed it, and image bytes must match their claimed type (checked by magic bytes). That blocks HTML or SVG disguised as an image.
  - **`GET /api/media/:key`** (new contract route): files are served immutable, with `nosniff` and a sandbox CSP. Non-media files always download instead of displaying.
- **Projects:** `thumbnailKey` and `mediaKeys` on create and update now work. The keys must belong to the user and the upload must have finished. Projects without an uploaded thumbnail still fall back to GitHub's OG card.

## Image resizing

`?w=` resizes images (to WebP) **when an `IMAGES` binding (Cloudflare Images) is configured**. Without it, the original is served. To turn it on, the owner enables Images on the account; then I add `"images": { "binding": "IMAGES" }` to `wrangler.jsonc`.

## For Sol (1.11) and Flash (avatar)

Flow: `createUpload` → `PUT uploadUrl` with the raw file and its exact Content-Type → use `key` in `thumbnailKey`/`mediaKeys`, or `url` for display.

## Tests

`test/integration/uploads.test.ts`: the happy path, wrong type, oversize, disguised HTML, someone else's key, attaching to a project, and unknown keys.
