# [2.4] DMs, collab requests, blocks (+ notification reads): Opus

- **DMs** (`core/messaging.ts`):
  - **Starting a conversation:** reuses the existing one-to-one conversation if there is one. Respects the recipient's DM policy: `everyone`, `followers` (the recipient must follow the sender) or `nobody`, each refused with a clear 403 message. Blocks in either direction refuse with "You can't contact this person."
  - **Reading:** listing messages returns newest first, and reading the newest page marks the conversation as read. The inbox shows a preview and an unread count. Non-members get a 404.
- **Collab requests:**
  - **Kinds:** `collab`, `build_permission` (the panel's "Request to build on this"; needs a project owned by the recipient) and `adoption`.
  - **Rules:** Turnstile is required. A duplicate pending request returns 409. Only the recipient can answer, and only once.
  - **Notifications:** sent on both the request and the answer.
- **Blocks and mutes:**
  - **Block:** stops DMs and requests both ways and removes follows both ways.
  - **Mute:** only silences notifications from that person.
- **Notifications:** new helper `core/notify.ts`. It never notifies you about your own actions, and never about someone you've blocked or muted. `listNotifications` (with `unreadCount`) and `markNotificationsRead` (ids or all) are real. Email delivery and digests come in 2.3.

For Sol (2.9): a 403 from `startConversation` carries a message that's ready to show as-is.

Tests: `test/integration/messaging.test.ts`.
