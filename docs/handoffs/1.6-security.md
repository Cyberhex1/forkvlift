# [1.6] Security on import: Opus

## What changed

- `core/safety/scan.ts` (it reads files only; nothing is ever run):
  - **Committed secrets:** flags risky filenames (`.env`, private keys, `.pem`, `credentials.json`, `.npmrc` …; `.env.example` and similar are allowed). It also checks up to 15 small config and script files for known key formats: AWS, GitHub, OpenAI, Anthropic, Stripe live, Slack, Google, and private keys.
  - **Suspicious install scripts:** checks npm lifecycle scripts (`preinstall`, `install`, `postinstall`, `prepare`) and root `.sh`/`.ps1` files for piping a download into a shell, running encoded or decoded commands, or reading SSH keys or credential stores.
- **On submit:**
  - Install-script findings become public "review before running" flags (`safety.flags`).
  - **Secrets are reported to the author only**, as a private notification that names the kind of key and the file. The secret itself is never stored or shown.
  - **New-account limits:** 3 projects a day for accounts under 7 days old, 10 a day after that (returns 429).
- **On curation:** the "No committed secrets" and "Not malware-flagged" chips now show real results, flagged repos lose 50 score points, and the flags carry over to the published curated card.
- **Already in place:** Turnstile on submit, comments, threads, requests and collab requests; rate limits on every write.

## Limits (honest)

- There's no known-malware hash list yet. The checks are heuristics, and the "review before running" notice still applies to everything.
- Large repos are only sampled (up to 15 files, 3 folder levels deep), so this doesn't replace GitHub secret scanning.

## Tests

- `test/scan.test.ts`: patterns and script heuristics.
- `test/integration/safety.test.ts`: private secret warning, public flags, clean repos, candidate chips, and new-account limits.
